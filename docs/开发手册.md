## 1. 开启真实 AI（3 步）

这个项目现在有**真实数据库**和**真实大模型**，不再全是写死的。

### 1.1 现在哪些是"真"的

| 功能 | 是真的吗 | 靠什么 | 需要 key 吗 |
|---|---|---|---|
| 衣橱（增/删/收藏/查） | ✅ 真数据库 | Node + SQLite（`server/data.db`） | 不需要 |
| 风格报告（结果页） | ✅ 真 AI | 大模型 | 需要 |
| 情景模拟 · AI 推荐 | ✅ 真 AI | 大模型（按天气+风格生成） | 需要 |
| AI 穿搭顾问（对话） | ✅ 真 AI | 大模型 | 需要 |
| 商品/杂志/社群等列表 | ❌ 还是 mock | 之后可入库 | — |

> 衣橱不需要 key：启动后端就是真数据库，能增删改查、刷新后还在。
> 其余三个 AI 功能需要填 key；没填会显示"AI 没连上"并回退本地示意，App 不崩。
> 密钥放在后端（`.env`），不会暴露到浏览器。

### 1.2 第 1 步：填你的 key

打开根目录的 **`.env`**，按你用的服务商改这几行（挑一行照着填）：

| 服务商 | AI_PROVIDER | AI_BASE_URL | AI_MODEL |
|---|---|---|---|
| DeepSeek | openai | https://api.deepseek.com | deepseek-chat |
| 通义千问 | openai | https://dashscope.aliyuncs.com/compatible-mode/v1 | qwen-plus |
| 智谱 GLM | openai | https://open.bigmodel.cn/api/paas/v4 | glm-4-flash |
| Kimi | openai | https://api.moonshot.cn/v1 | moonshot-v1-8k |
| OpenAI | openai | https://api.openai.com/v1 | gpt-4o-mini |
| Claude | anthropic | （留空） | claude-haiku-4-5-20251001 |

然后把 **`AI_API_KEY=`** 后面填上你的 key。例（DeepSeek）：

```
AI_PROVIDER=openai
AI_API_KEY=sk-你的key
AI_MODEL=deepseek-chat
AI_BASE_URL=https://api.deepseek.com
```

### 1.3 第 2 步：同时启动前端 + 后端

```bash
npm run dev:all
```

（也可分开：一个终端 `npm run server`，另一个 `npm run dev`。改了 `.env` 要重启 `server`。）

### 1.4 第 3 步：看效果

打开前端 → 首页「开始个性化创建 / 身形测试」→ 做完 5 步 → **风格报告页**。
- 顶部显示 **✨ 以下由 AI 实时生成**，下面总结、雷达分数、推荐配色、穿搭推荐、造型建议都是大模型**实时生成**。
- 点「换一份」重新生成。
- key 没填对会显示「AI 没连上」并自动回退本地示意数据（App 不崩）。

### 1.5 自检后端有没有配好

浏览器打开 <http://localhost:8787/api/health> ，看到 `"hasKey":true` 就说明 key 读到了。

### 1.6 这层怎么工作（架构）

```
浏览器(Vue)  ──/api/style-report──►  Node 后端(server/index.mjs)  ──►  大模型API
   结果页                              (保管 key、拼提示词、解析JSON)      (DeepSeek/通义/Claude…)
```

- 前端代码：`src/api/ai.ts`（发请求）、`src/views/ResultReport.vue`（展示）。
- 后端代码：`server/index.mjs`（注释很全，想加别的 AI 功能照着扩）。
- 想让**别的功能也接 AI**，在 `server/index.mjs` 里照着 `/api/style-report` 再加一个接口即可。

## 2. 部署上线指南

### 2.1 架构总览

```
用户 → 微信小程序 (uni-app) ──→ Nginx (HTTPS) ──→ Node.js (Express, port 8787)
                            ──→ FastAPI  (可选, port 8788)
                                                 ├── MySQL (3306)
                                                 └── SQLite (开发默认)
```

### 2.2 后端部署（阿里云轻量 / 腾讯云）

**① 环境准备**

```bash
# 安装 Node.js 18+
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
sudo apt-get install -y nodejs

# 安装 MySQL
sudo apt-get install -y mysql-server
sudo mysql_secure_installation

# 或者用 Docker
docker run -d -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=yourpassword \
  -e MYSQL_DATABASE=lingxi \
  --name lingxi-mysql mysql:8
```

**② 数据库初始化**

```bash
mysql -u root -p < server/schema.sql
```

**③ 配置环境变量**

```bash
# 生产 .env
cp .env .env.production
# 编辑 .env.production:
#   DB_TYPE=mysql
#   MYSQL_HOST=localhost
#   MYSQL_PASSWORD=yourpassword
#   JWT_SECRET=随机生成的长字符串
#   AI_API_KEY=你的真实key
```

**④ 启动后端**

```bash
# 安装 PM2
npm install -g pm2

# 启动 Node 后端
pm2 start server/index.mjs --name "lingxi-api" \
  --node-args="--experimental-sqlite" \
  --env-file .env.production

# 可选：启动 Python AI 层
cd ai-server && pm2 start "venv/bin/uvicorn main:app --host 0.0.0.0 --port 8788" --name "lingxi-ai"

pm2 save && pm2 startup
```

**⑤ Nginx 反向代理 + HTTPS**

```nginx
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    location /api/ {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 支持
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
    }

    location / {
        root /var/www/lingxi-h5;
        try_files $uri $uri/ /index.html;
    }
}
```

HTTPS 证书（Let's Encrypt 免费）：
```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

## 3. 页面搭建规范

> 适用于 **web（Vue3 + TS H5）** 端。你负责搭建**指定的一个页面**（一个 view 文件，复杂时可在自己的子文件夹里拆子组件）。严格照本规范，保证和已有页面风格一致。
> 迁移到 miniapp 时的适配（`<div>`→`<view>`、`@click`→`@tap`、`router`→`uni.*`）见《项目总纲》第 6.8 节。

### 3.0 铁律

1. **只创建你被分配的 view 文件**（及该页面专属子组件，放自己的子文件夹、用页面名前缀命名，如 `MallProductSheet.vue`）。
2. **绝对不要修改**这些共享文件：`router/index.ts`、`main.ts`、`App.vue`、`assets/styles/*`、`components/BottomNav.vue`、`components/PageHeader.vue`、`components/SegTabs.vue`、`components/TileImage.vue`、`components/ProductCard.vue`、`components/SectionTitle.vue`、`data/*`、`stores/*`。路由已接好，指向你要创建的文件路径。
3. 语言：Vue3 `<script setup lang="ts">`。TS 是 **strict + noUnusedLocals + noUnusedParameters**——**不要留没用到的 import / 变量 / 参数**，否则打包报错。
4. 图片一律走 `<TileImage :src="...">`，`src` 取 mock/接口里的 `img` 字段，缺图自动回落到渐变色块 + emoji（素材路径见 `docs/图片素材清单.md`）。不要自己写 `<image>`。
5. **图标一律用 `<UiIcon>`，不要用 emoji。** emoji 在 iOS / 安卓 / 微信开发者工具三端字形不同，设计稿对不齐。emoji 只保留在「缺图占位」和「表情语气」两种场景（如 TileImage 的兜底、空状态插图）。
6. 全中文文案，粉紫少女风，圆角卡片、柔和阴影。参考 `views/Home.vue`、`views/Closet.vue`。

### 3.1 目录 & 别名

- `@` = `src`。例：`import TileImage from '@/components/TileImage.vue'`。

### 3.2 页面骨架（必须这样）

每个页面根是一个纵向 flex 的满高容器：

```vue
<template>
  <div class="page">
    <!-- 有底部 tab 的页面（首页/Ai/衣橱/商城/我的）：顶部可无 header -->
    <!-- 二级页面：顶部放 <PageHeader title="xxx" /> -->
    <PageHeader title="情景模拟" />

    <div class="body scroll-y hide-scrollbar">
      <!-- 你的内容 -->
    </div>

    <!-- 只有 5 个 tab 主页面才加这行；二级页面不要加 -->
    <BottomNav active="closet" />
  </div>
</template>

<style scoped>
.page { height: 100%; display: flex; flex-direction: column; }
.body { flex: 1; min-height: 0; padding: 12px 16px 16px;
        display: flex; flex-direction: column; gap: 14px; }
</style>
```

- 底部 tab 主页面（active 值）：`home` / `ai` / `closet` / `mall` / `me`。
- 二级页面用 `<PageHeader title="..." />`，自带返回键（默认 `router.back()`；可传 `to="/home"` 指定目标）。

### 3.3 样式在哪里改（`miniapp/src/styles/`，App.vue 已全局 @import）

**全站样式只有这三个文件，页面里不要重复定义。**

| 文件 | 装什么 | 什么时候改它 |
|---|---|---|
| `styles/tokens.css` | 设计变量：颜色 / 圆角 / 阴影 / 间距 / **层级** | 换主题色、调圆角、改全局间距 |
| `styles/base.css` | 页面骨架 `.page` `.body`、滚动、横滑 | 调页面通用边距、滚动行为 |
| `styles/components.css` | 通用类 `.btn` `.card` `.chip` `.empty` `.mask` `.sheet` `.toast` `.grid-2` `.hairline*` | 调按钮、卡片、弹层、空态的统一样式 |

> ⚠️ **还有第四个文件：`miniapp/src/uni.scss`。**
> 那里放的是 **uv-ui 组件库的 SCSS 主题变量**（`$uv-primary` 等）。
> uv-ui 组件读 SCSS 变量，读不到上面的 CSS 变量，所以两边是**两套**。
> **改主色要动两处**：`tokens.css` 的 `--pink-deep` 和 `uni.scss` 的 `$uv-primary`。

**视觉语言对齐 uv-ui**（2026-08-17 起）：单一主色、冷灰中性色、近乎方角、**发丝线分隔不靠阴影**、无渐变。

- 主色：`--pink-deep`（`#ff5c9d`）、`--price`（同值，价格专用）
- 主色浅底：`--pink-soft`（`#ffeaf3`，标签底/选中底）
- **已收敛的别名**（变量名保留、值都指向主色或语义色，调用点不用改）：
  `--pink` `--purple` `--purple-deep` → 主色；`--mint-deep` → `--success`；`--mint` → success 浅底；`--purple-soft` → `--pink-soft`
- 语义色：`--danger`(`#f56c6c`) `--warning`(`#f9ae3d`) `--success`(`#5ac725`) `--info`(`#909399`)
- 文字：`--text-1`(`#303133` 主) `--text-2`(`#606266` 次) `--text-3`(`#909193` 弱) `--text-4`(`#c0c4cc` 最弱) `--text-on-brand`(白)
- 面：`--bg-page`(`#f3f4f6` 页面底) `--surface`(白) `--surface-soft` / `--surface-glass`(**都已改成实心白**) `--surface-placeholder`(`#f3f4f6` 缺图底)
- 线：`--line`(`#dadbde`) `--hairline`(`0.5px solid #dadbde`，直接 `border: var(--hairline)`)
- 圆角：`--radius-sm`(6rpx) `--radius`(8rpx) `--radius-lg`(16rpx) `--radius-pill`
- 阴影：`--shadow-soft` `--shadow-card`（都已收到近乎不可见）`--shadow-float`（弹层用，保留实感）
- 间距：`--gap-xs` `--gap-sm` `--gap` `--gap-lg` `--page-x`(30rpx，对齐 uv-cell) `--page-top` `--page-bottom`
- **层级：`--z-raised` `--z-float` `--z-sticky` `--z-mask` `--z-sheet` `--z-toast`**

**已删除的变量**（别再引用）：`--bg-gradient`（粉紫渐变页面底 → 换成 `--bg-page`）。
`--brand-gradient` 变量名还在但**已经不是渐变**了，值是纯色 `#ff5c9d`——它有 63 处调用点，保留名字是为了不动那些页面。

> ⚠️ **z-index 一律用上面的变量，不要手写数字。**
> 之前 `.toast` 在 8 个页面里各写了 10 / 40 / 50 / 60，`.mask` 写了 20 / 30 / 40 / 50，
> 结果 z-index 小的 toast 被别的页面的遮罩盖住。层级必须全站统一排序才不会互相压。
>
> uv-ui 自己的弹层默认 `z-index: 10075`，比这套高得多，永远盖在我们的层之上。
> 目前这是想要的结果；需要反过来时给那个 uv 组件传 `:z-index`，**不要抬高上面的数字**。
>
> ---
>
> ⚠️ **rpx / px：uv-ui 保持 px，本项目保持 rpx，两套并存 —— 不要试图统一。**
> uv-ui 有个全局开关 `uni.$uv.config.unit`（默认 `'px'`），改成 `'rpx'` 看起来正好能对齐本项目的 2194 处 rpx。**试过，是陷阱**：
> 它的 `addUnit()` 也作用于 prop 默认值，全库 **179 个数字型默认值**（`uv-tabbar` 的 `iconSize: 20` 等）都是按 px 写的，开关一切统统减半，图标和间距集体缩一半，**而且不报错**。
> 375px 基准屏上两套单位完全等效；非基准屏上 uv-ui 组件不缩放、我们的内容随屏缩放。这是 uni-app 混用 uView 系库的常态，可接受。
> 需要某个 uv 组件跟着屏宽缩放时，在**那个调用点**传 rpx 字符串（`:size="'40rpx'"`，`addUnit` 遇到非纯数字会原样返回），不要做全局换算。
>
> ---
>
> ⚠️ **`uni.scss` 里的 `$show-*` 开关一个都不能删。**
> uv-ui 的工具类（`.uv-border-top` / `.uv-line-1~5` / `.uv-reset-button` / `.uv-hover-class`）
> 藏在 `libs/css/variable.scss` 的 `@if variable-exists(...)` 后面，开关没定义就**静默不生成**：
> 分隔线全部消失、文字截断失效、组件内 `<button>` 保留微信原生灰底、没有按压反馈。不报错，极难排查。

### 3.4 全局类（直接加 class，别再自己写一份）

- 按钮：`.btn` + `.btn-primary` / `.btn-ghost` / `.btn-disabled` / `.btn-sm`
- 骨架：`.page`（纵向满高）、`.page-stage`（内部有绝对定位浮层时加）、`.body`（滚动区）
  - `.body-top`（顶到状态栏的 tab 主页面）、`.body-stack`（纵向+统一间距）、`.body-flush`（左右贴边）
- 卡片：`.card` / `.card-glass`（浮层，**已不是毛玻璃**：uv-ui 没有半透明面，而且 `backdrop-filter` 在安卓小程序本来就不生效）
- 发丝线：`.hairline` / `.hairline-t` / `.hairline-b`（`0.5px solid #dadbde`）——**uv-ui 靠线分隔，不靠阴影**，列表型页面主要用这三个
- 标签：`.tag-pill` / `.tag-pill-brand`（浅粉底）、`.chip` / `.chip.on`（可点筛选片）
- 网格：`.grid-2` `.grid-3`
- 空态：`.empty` `.empty-title` `.empty-sub` `.empty-btn`
- 弹层：`.mask`（+`.mask-center`）/ `.sheet`（+`.sheet-center`）/ `.sheet-title` / `.toast`
- 滚动区加 `.scroll-y.hide-scrollbar`；横滑 chips 用 `.row-scroll`

**页面 scoped style 里只写「这一页独有」的差异**（比如某处的 padding）。
凡是别处也可能用到的，提到 `components.css` —— 复制一份就是下一次「到处改」的起点。

> 查重工具：`node scripts/css-audit.mjs page body empty toast mask`
> 列出某个类名在多少文件里被重复定义、有几种写法。
> `node scripts/css-migrate.mjs [--apply] 类名…` 批量删掉与全局重复的 scoped 规则
> （scoped 编译成 `.x[data-v-…]`，优先级更高，不删全局的就不生效）。

### 3.5 共享组件 API（直接用标签复用，别重造）

> ## ⚠️ 组件一律靠 easycom 自动注册，**不要在 .vue 里显式 `import` 组件**
>
> 模板里直接写 `<TileImage …/>` / `<ProductCard …/>` / `<uv-image …/>` 就行。三种解析途径：
> - `components/X/X.vue` → `easycom.autoscan: true` 自动扫到，**不需要任何配置**
> - `uv-*` → `pages.json` 的 `"^uv-(.*)"` 规则 → uv-ui
> - **页面级组件**（`pages/create/CreateBasicInfo.vue` 这类不在 `components/` 下的）
>   → `pages.json` 里已为它们逐组加了 easycom 规则（create / mall / scene / test 四组）。
>   新增页面级组件时**要在那里补一条规则**，不要写 `import X from './X.vue'`。
>
> **加了显式 import 会导致全站白屏**，而且报错完全指错方向：
> ```
> module 'utils/icons.js' is not defined, require args is '../../utils/icons.js'
> Page "pages/home/home" has not been registered yet
> ```
> 文件在磁盘上、`node --check` 通过、能 `require`、路径也对 —— 但小程序说模块不存在。
>
> 机制：uni-app 把**显式 import 的组件**编译成 marker **之后**的 `const`，而 easycom 组件是**内联**在 marker 里的。
> 两者混在同一个文件里，marker 就退化成前向引用：
> ```js
> Math||((()=>"…uv-image.js")+n)();   const n=()=>"./MallDetailSheet.js"
> //                          ^ n 在声明之前被引用
> ```
> 运行时被 `Math||` 短路了不抛错，但微信开发者工具要解析这几行 marker 来建依赖图，
> 它在 `+n` 处分析失败，于是没把本文件 `require` 的普通模块记为依赖，
> `ignoreDevUnusedFiles`（工具默认开启）就把那个模块从调试包里剔掉了。
>
> 全靠 easycom 时 marker 是干净的内联形式 `+(()=>"…")`。
>
> **注意区分**：`import` 普通模块（`@/utils/*`、`@/data/*`、`@/api/*`、`@/stores/*`）是正常的、必须的，
> 只有**组件**（.vue）不要显式 import。
>
> 复查手法（改完组件引用后跑一遍）：
> ```bash
> # 1. 源码层：不该有任何组件 import
> grep -rn "^import .* from '@/components/\|^import .* from '\./.*\.vue'" miniapp/src
> # 2. 产物层：扫 marker 里的前向引用（这是唯一的 ground truth）
> node -e "…" # 见 memory 或直接 grep 产物里的 Math||( 段落
> ```
> 已加保险：`project.config.json` 的 `setting` 里设了
> `ignoreDevUnusedFiles: false` + `ignoreUploadUnusedFiles: false`。

**`<TileImage>` —— 万能图片位（有图显图，缺图回落占位）**
```
props: src?: string(图片路径，缺省/加载失败则回落到中性浅灰占位 + 线条图标) ,
       emoji?: string(查表转成线条图标，见 utils/icons 的 iconForEmoji) ,
       icon?: IconName(显式指定占位图标，优先级高于 emoji) ,
       ratio?: string(默认 '1 / 1'，如 '3 / 4'；用 padding-top 撑开，小程序也生效) ,
       fit?: 'cover'|'contain'(默认 cover) , fill?: boolean(撑满父高，此时忽略 ratio) ,
       label?: string , rounded?: string(默认 var(--radius)) ,
       tint?: boolean(默认 false；true 才用 from/to 画渐变底) , from?/to?: string
```
例：`<TileImage :src="g.img" emoji="🧥" ratio="3 / 4" />`
> 内层用的是 `uv-image`（自带懒加载 + 淡入）。缺图 / 加载失败一律回落到
> 中性浅灰底 + UiIcon 线条图标，**不要再传 from/to 画彩色渐变块** ——
> 那是第一版设计稿的做法，已作废（彩色块 + 图标是「卡通感」的主要来源）。

**`<UiIcon>` —— 线性图标（easycom 自动注册，不用 import）**
```

       tone?: 'dark'|'soft'|'muted'|'brand'|'purple'|'white'(默认 soft) ,
       color?: string(字面色值，优先于 tone；不能传 CSS 变量) , strokeWidth?: number(默认 1.7)
```
例：`<UiIcon name="cat-shoes" :size="38" tone="dark" />`
> 实现是「运行时拼 SVG → base64 → background-image」。WXML 不支持内联 `<svg>`，
> `<image src="x.svg">` 在部分安卓机不渲染，所以走这条路。
> 新增图标：在 `icons.ts` 的 `ICON_PATHS` 里加一条 24×24 viewBox 的 path 数组即可。
