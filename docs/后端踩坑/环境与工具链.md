## 3.1 MySQL 在 3308，但 Docker Desktop 不自启

- 容器 `lingxi-mysql8`（MySQL 8.4.11）→ `localhost:3308`，卷 `lingxi-mysql8-data`
- 带 `--restart unless-stopped`，但 **Docker Desktop 本身不会自启**（实测中途退过一次，
  表现是 `ECONNREFUSED 127.0.0.1:3308`）。**开发前先起 Docker。**
- 本机还有个 MySQL80 服务在 **3307**（`my.ini` 里配的），密码和项目 `.env` 里的不一样。
  别混。

## 3.2 git 代理端口：Clash Verge 是 7897 不是 7890

**现象**：`git push` 报 `Failed to connect to 127.0.0.1 port 7890`，但代理明明开着。

**根因**：Clash Verge 新版把默认混合端口从 **7890 改成了 7897**，git 的配置还停在旧值。

```bash
git config http.proxy  http://127.0.0.1:7897
git config https.proxy http://127.0.0.1:7897
```

**⚠️ 当前只改了本仓库级，全局配置仍是 7890** —— 其它仓库 push 会踩同一个坑。
想一次性修掉加 `--global`。

诊断命令：`netstat -ano | grep LISTENING | grep 789` 看代理实际在哪个端口。

## 3.3 Windows 下 pkill 杀不掉 node，要按端口杀

**现象**：改完代码重启服务，测出来还是旧行为 —— 因为 `pkill -f "node ... index.mjs"`
在 Windows 的 Git Bash 里匹配不到，旧进程还占着 8787，新进程 `EADDRINUSE` 直接退出，
而测试打的是旧进程。**一度以为是自己的修改没生效。**

```bash
PID=$(netstat -ano | grep LISTENING | grep ":8787" | head -1 | awk '{print $NF}')
taskkill //PID "$PID" //F
```

**教训**：重启后先确认端口真的换了进程，或者 `grep -c EADDRINUSE` 看一眼启动日志。

## 3.4 其它小坑

| 坑                                          | 解                                                            |
| ------------------------------------------- | ------------------------------------------------------------- |
| `node -e` 里写 top-level `await` 报编译错   | 加 `--input-type=module`                                      |
| Git Bash 的 `/tmp` 和 node 看到的不是同一处 | node 会把 `/tmp/x` 解析成 `E:\tmp\x`，用项目内相对路径        |
| Windows 终端传中文给 curl 会变乱码          | 不是应用 bug。用 `--data-binary @file.json` 传 UTF-8 文件验证 |
| `stdout` 打日志会让 MCP 客户端解析失败      | stdio 传输把 stdout 当 JSON-RPC 通道，**日志只能走 stderr**   |
| 父进程的 `--env-file` 不会传给子进程        | `StdioClientTransport` 要显式传 `env: process.env`            |
| 百炼 embedding 单次超过 10 条报 400         | `InvalidParameter`，批量上限是 10（2026-09-08 实测）          |
| 格式化 `rag-docs/*.md` 会触发索引全量重建   | 缓存靠 mtime 判失效，别对知识库跑 prettier                    |
