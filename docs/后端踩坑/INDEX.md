## 四、三条贯穿全篇的判断标准

散在各条里，提到这儿方便回看：

1. **换掉数据库要不要跟着改？** 要 → repo；不要 → service。（[§1.5](./分层与数据访问.md#15-什么该放-repo什么该放-service)）
2. **能交给数据库保证的事，不要交给 JS 的 `if`。** `affectedRows` 挡越权、`UNIQUE` 挡并发，
   都比"查出来再判断"可靠——后者漏写一个 `if` 就漏数据。（[§1.6](./分层与数据访问.md#16-转换层缺失同一个职责两个方向的错位)、[§2.7](./分层与数据访问.md#27-默认分类-上衣-和枚举-top-对不上)）
3. **静默失败比崩溃难查得多。** 返回空数组不报错（[§2.6](./分层与数据访问.md#26-颜色筛选永远返回-0-条)）、
   把请求发到错端点报个 404（[能力矩阵](./能力矩阵与待办.md)），都比明确抛错浪费时间。
