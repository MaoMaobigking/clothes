- **「已实现，未实测」**= 代码按官方 API 形状写了（`client.mjs` 的 `structuredAnthropic` / `callAnthropic`、
  `stream.mjs` 的 `streamAnthropic`），但**手上没有 Anthropic key，一次都没真跑过**。
  不能当"支持"讲。
- **「未实现」**= `tools.mjs` 的 `aiChatWithTools` 只写了 OpenAI 兼容协议。
  Anthropic 的工具协议形状不同（`tool_use` / `tool_result` 内容块 + `stop_reason` 判定），需要单独一条分支。

**为什么不干脆删掉 Anthropic**：那些实现是照真实 API 形状写的，删掉是更大更有风险的改动，拿到 key 就能验。
**标注"未实测"比删掉更诚实，也比假装支持更诚实。** 面试照矩阵讲反而是加分项。

**为什么不留静默陷阱**：`aiChatWithTools` 已在入口显式抛 `TOOL_CALLING_UNSUPPORTED_PROVIDER`（501）。
补这个守卫之前，`AI_PROVIDER=anthropic` 会把 OpenAI 形状的请求发到
`https://api.anthropic.com/chat/completions` 并带错认证头，报出来是个让人摸不着头脑的 404/401 ——
看着像网络或密钥问题，实际是"这条路根本没实现"。**静默陷阱比明确不支持难查得多。**

### token 成本统计（2026-09-10 补齐，原来是这张表的第一条边界）

**原来的问题**：`ai_logs` 表和 `prompt_tokens` / `completion_tokens` 两列早就在、
`logAiCall` 也收这两个参数，**但底层三个函数（`aiComplete` / `aiChatStream` / `aiChatWithTools`）
都只返回文本字符串**，从没把 provider 响应里的 `usage` 透出来。所以那两列长期固定是 0 ——
「我做了 token 成本统计」当时是不能说的。

**怎么补的**：新增 `services/ai/usage.mjs`，用 `AsyncLocalStorage` 收集用量。
`withAiLog` 开一个作用域，期间任何深度的模型调用都把 `usage` 报上来，**函数签名一个都没改**。

**为什么不是把返回形状改成 `{ text, usage }`**（这是这条改动里唯一需要想一下的地方）：

1. **一次逻辑调用底下可能有多次 HTTP 往返。** `aiChatWithTools` 最多跑 5 轮，
   `generateReport` 走兜底时也可能连打两次。返回值只能带最后一次的数字，
   而「这次对话花了多少钱」问的是**总和**。
2. **中间层返回的是业务对象。** `generateReport` 返回报告对象、`generateSceneOutfits`
   返回搭配数组，包成 `{ data, usage }` 会污染七处调用方，
   而这一层本来就不该认识 token 这种计费概念。

**实测数据**（`npm run check:usage`，DeepSeek）：

| 场景                   | prompt   | completion | 模型往返次数 |
| ---------------------- | -------- | ---------- | ------------ |
| 普通对话               | 53       | 51         | 1            |
| SSE 流式               | 53       | 43         | 1            |
| tool-calling（问天气） | **1055** | —          | **2**        |

**tool-calling 的 prompt token 是普通对话的 20 倍** —— 因为工具定义和上一轮的工具结果
每轮都要重发。这条数据是「按 scene 拆出哪个功能最烧钱」的直接证据，
也是为什么 `model_calls` 要和 token 一起记：同一个 scene 下 token 高，
可能是提示词长，也可能是工具循环多跑了两轮，不记往返次数就分不出来。

**两个诚实边界**：

1. **流式的 token 依赖 provider 支持 `stream_options: {include_usage: true}`。**
   DeepSeek 支持（上表已实测）。不支持的兼容代理会 400，
   代码里照 `structuredFormatRejected` 的既有做法**只在确认是这个参数被拒时**摘掉重试，
   此时流式那条就记不到 token —— 是已知边界，不是 bug。
2. **`cache_hit_tokens` 实测是 0。** DeepSeek 的上下文缓存要重复前缀才命中，
   验收脚本每次问的话不一样，所以没命中。**不能拿这个 0 反推"缓存没生效"** ——
   只说明这次没命中。

**仍然没有的**：看板和告警。目前只落表、靠 SQL 查。

### 另一条必须主动说清的边界

**天气目前全是降级值**：`OPENWEATHER_API_KEY` 没配，`resolveWeather` 永远走
`buildFallbackWeather`（按经纬度+季节派生）。代码里真实 API 路径是通的，填上 key 立刻变真 ——
但在填之前，**只能说"接了真实天气 API，当前用降级数据演示"**。
工具返回值带 `source` 字段（`located` 实时 / `fallback` 推算），让模型知道这条数据的可信度。
