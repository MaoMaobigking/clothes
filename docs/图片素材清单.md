# 图片素材清单

> 版本：v2.0　日期：2026-09-09　依据：`docs/六功能需求规格与验收清单.md` §14
> 用途：把代码里已经预留好路径、但素材还没到位的图集中列出来，交给素材同学一次配齐。
>
> v2.0 变更：客户交付第一批实拍素材（76 张），人台、场景、整套 look 三组已到位；
> 场景从六个抽象场景改成十个具体地点（见 D 组）。

## 怎么用这份清单

- **路径就是约定**。代码里已经按下表的路径去取图，图片按文件名丢进对应目录即可生效，**不需要改代码**。
- **缺图不会报错也不会白块**。所有位置都做了中性占位回落（色块 + emoji / 渐变底 / 「暂无素材」文案），
  符合 §14「缺失素材时显示中性占位，不使用卡通图替代」。
- **目录根**：`miniapp/src/static/`。表里的路径都是运行时路径（以 `/static/` 开头），
  对应磁盘上的 `miniapp/src/static/...`。
- **格式**：照片用 JPEG/WebP，需要透明背景的用 PNG。
- 「淘口令」一列指该素材对应的商品是否需要配套淘口令；淘口令本身写在数据里（见文末），不是图片。

## B. 3D 人台（功能一 §7.9、功能三 §9.5）

规格要求「半写实 3D 人台或模特，不使用卡通小人」。

建议尺寸：**200 × 1190 px**，即与现素材保持同比例（93 : 553 ≈ 1 : 5.95）；
格式 **PNG，必须透明背景**。

> ⚠️ **换素材时必须保持构图**：`components/AvatarViewer` 里的 `widthProfile` 有 9 个控制点，
> 分别对应「头顶 0 / 颈 0.13 / 肩 0.22 / 胸腰过渡 0.36 / 腰 0.45 / 胯 0.52-0.57 / 腿 0.72 / 脚 1.0」
> 这些高度比例，是照着现素材的构图量出来的。新素材如果留白更多、人物在画面里的位置变了，
> 肩腰臀的缩放会错位，需要同步调这 9 个数。最省事的做法是**新素材沿用现素材的裁切构图**：
> 头顶紧贴上边缘、脚底紧贴下边缘、人物水平居中。

> ✅ **2026-09-09：客户实拍素材已到位**，五张全部替换成真人全身照（纯白底 JPEG，
> 长边 1300，约 30–80KB）。构图正好符合上面那条要求：人物填满画面高度、水平居中，
> 所以 `widthProfile` 那 9 个控制点没有改动。
>
> 附带解决的两件事：
>
> 1. `back.jpg` / `back-male.jpg` 第一次有了真素材。`AvatarViewer` 的「背面演示」
>    角标改成只在**没有**真背面图时才显示（传 `{ front: x, back: x }` 顶替时仍会标注），
>    `pages/result/index.vue` 的 `:frames` 已指向真背面图。
> 2. 旧的 `front-male.png`「其实是同一张女性照片，用棕色方块盖住头发假装短发」——
>    现在是真的男性人台，§7.9「按性别呈现差异」不再只靠肩臀系数。
>
> ⚠️ **仍需补的**：客户给的是**白底不透明 JPEG**，不是透明底 PNG。`AvatarViewer` 把人台
> 竖切成 24 片分别横向缩放，不透明背景会让这个矩形的左右边缘产生约 1px 的台阶，
> 组件里的 `drop-shadow` 也没有意义。要彻底解决还是得要抠图后的透明 PNG。

| 文件名           | 用途                                                       | 目录                    | 淘口令 |
| ---------------- | ---------------------------------------------------------- | ----------------------- | ------ |
| `front.jpg`      | 女性人台正面                                               | `/static/images/model/` | 否     |
| `front-male.jpg` | 男性人台正面                                               | `/static/images/model/` | 否     |
| `back.jpg`       | 女性人台背面（§7.9 / §9.5 背面切换）                       | `/static/images/model/` | 否     |
| `back-male.jpg`  | 男性人台背面                                               | `/static/images/model/` | 否     |
| `outfit.jpg`     | 搭配展示用人台（`MODEL_IMAGES.outfit`，`constants/ui.ts`） | `/static/images/model/` | 否     |

五张都以 `.jpg` 落盘 —— `constants/ui.ts` 的 `MODEL_IMAGES` 里写的就是 `.jpg`，
换成 PNG 的话要同步改那份常量。

## D. 场景与新品目录（功能四）

场景从原来六个抽象场景（daily / business / date / travel / academy / cosplay）改成
**十个具体地点**。客户实拍素材是通勤 + 社交两条线的空场景，「学院风」「cosplay」在这批
素材里压根没有对应场景，所以场景表跟着素材重建了。

改一处场景 key 要同步三个地方，它们是一套 key：

- `miniapp/src/constants/scene.ts` 的 `SceneKey` 与 `SCENE_OPTIONS`（前端唯一来源）
- `server/constants/scene.mjs` 的 `SCENE_DEFINITIONS`（含每个场景的 `slots`）
- `server/seeds/scene-catalog.json` 的 `sceneKey`

`miniapp/src/mocks/demo.ts` 的 `SCENES_RAW` 也列了一份（自由搭配页用），改表时别漏。

## 上传规范（§14）

- 照片：JPEG / PNG / WebP；需要叠加或去背的一律 PNG 透明背景。
- 封面比例：1:1 或 4:3。
- 视频：MP4（本轮无视频需求）。
- 单文件大小上限待云存储额度确定后再定；当前均为随包静态资源，建议单张 ≤ 200KB，
  人台图 ≤ 500KB，避免小程序主包超限。
- 缺失素材一律中性占位，禁止用卡通图替代。
