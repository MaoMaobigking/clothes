## Context

功能一~三已按《前三功能补齐实施计划》闭合到代码完成（手测未做）。功能四~六在 2026-08-14 前后依次合入本地 `main`，此后没有对着规格逐条核对过，本文是这次核对的结果。

三处最大的差距：

1. **功能四的「效果图」和「海报」都还没有真实衣物**。`pages/scene/index.vue:460-478` 的舞台是背景图 + 滤镜遮罩 + 静态人台，衣物只在下方九宫格里列出；`exportPoster()`（同文件 275-350 行）画的是渐变底 + 人台 + 文字清单。§10.7 要求「使用当前真实衣物照片与统一模特或 3D 模板组合」，§10.10 要求海报「包含真实搭配、场景背景和滤镜」。功能二的 C1/C2 已经把这两件事做对了，功能四直接复用即可。
2. **商城页仍是 mock**。`pages/mall/mall.vue:5` 从 `data/mock.ts` 取商品，服务端 `scene_catalog` 里没有对应记录，因此 §4.4「商品必须包含淘宝链接和淘口令」站不住，批次 0B 为商城预留的 `cart_items.item_type='catalog'` 也一直没被真正用到。
3. **「我的搭配」分裂成三处**。`closet.vue:199` 的二级 tab 只有功能二收藏，`pages/outfits/index.vue:5` 只列功能四场景模板，`me.vue` 菜单指向后者。§8.11 和 §10.10 说的是同一个「我的搭配」。

另有两处流程债：功能六的 `npm run check:community` 自合并起从未执行过；`miniapp/src/static` 下当前只有 2 个文件，`docs/图片素材清单.md` 的约 130 张全部靠占位。

## 决策

- **商城目录复用 `scene_catalog`**，不另起 `mall_products`。功能四新旧混搭本来就从它选品，两份商品数据没有必要。
- **本轮不做 Git 收尾**：不合回 `main`、不推 `origin`、不删 `codex/feature-*` 分支与 `.worktrees/feature-5`。当前分支 `feat/登录与演示账号-0A` 领先 `origin/main` 29 个提交的状态保持不变。

## 实施方案

### 批次 5 — 功能四（§10）

- `miniapp/src/pages/scene/index.vue`：舞台段落改用 `components/OutfitPreview`，把 `plan.items` 的真实 `imageUrl` 按 category 叠到人台上，保留场景背景图与 `stage-filter` 遮罩在下层；对比模式两张卡共用同一模特与背景，只换衣物层，满足 §10.8「两版使用相同模特和场景背景」。
- `components/OutfitPoster/OutfitPoster.vue`：增加 `background`（场景底图）与 `filterStyle`（滤镜遮罩）两个可选 prop，功能二调用不传即维持现状。`scene/index.vue` 的 `exportPoster()` 整段替换为该组件，删掉 `createCanvasContext` 老路径，H5 走组件已有的长按保存兜底。§10.9「海报导出保留当前滤镜」由 `filterStyle` 承接。
- 后端商城目录（复用 `scene_catalog`）：
  - `server/repositories/sceneRepo.mjs` 补 `listCatalogProducts({ category })`；确认 `scene_catalog` 已有 `taobao_url` / `taokouling` 字段，缺则按 `ensureColumn()` 增量迁移并在 `ensureSceneCatalog()` 的种子里补齐。
  - 新增 `server/routes/mall.mjs`（`GET /api/mall/products`、`GET /api/mall/products/:id`），`index.mjs` 挂载。
- `miniapp/src/pages/mall/mall.vue` + `MallDetailSheet.vue`：去掉 `data/mock.ts` 的 `MALL_PRODUCTS` / `MALL_CATEGORIES`，改接新接口；购买复用功能三的淘口令弹窗（§4.4 小程序写剪贴板、H5 先试跳转再复制）；加购走 `/api/cart` 的 `item_type='catalog'`。

### 批次 6 — 功能五（§11）

- `miniapp/src/pages/custom/orders.vue`：申请详情加状态时间轴（已提交 / 设计稿 / 打样 / 生产中 / 发货），接后端已有的状态字段；演示推进按钮只对演示账号显示，不做真实履约（§16）。

- 回归 `check:custom`、`check:custom:http`，确认登录与购物车统一没有波及功能五。

### 批次 7 — 功能六（§12）

- `pages/magazine/index.vue` 改为 `redirectTo` 到 `pages/community/index?tab=magazine`（或直接删页），`pages.json` 与 `data/mock.ts` 的 `MAGAZINES` 一并清理，避免两套杂志数据并存。
- 起后端执行 `npm run check:community`，覆盖点赞 / 评论 / 收藏 / 举报后过滤 / 书签笔记 / 教程完成与积分 / 看板统计，按结果修问题。

### 批次 8 — 我的搭配合一（§8.11 §10.10）
