## Context

`docs/六功能需求规格与验收清单.md` 是本项目的验收依据。功能一到功能六的代码都已存在并合并进本地 `main`（最新 `3f5aed9`），但功能一~三与规格仍有可枚举的差异，主要集中在三处：

1. **§5「登录与演示账号」完全没实现**。前端 `miniapp/src/api/http.ts:77` 的 `ensureToken()` 在无 token 时直接调 `/api/auth/dev-token` 自动建号，没有登录页、没有账号密码登录、没有四类预置演示账号、`me.vue:59` 的管理员入口直接跳看板不校验密码。功能一~三验收里的「数据重新打开仍存在」「演示账号数据提前准备」因此站不住。
2. **购物车分裂成两套且互相看不见**。功能二用 `/api/cart` + `feature2_cart_items`（`server/repositories/cartRepo.mjs`），功能三用 `/api/accessory-cart` + `cart_items`（`server/repositories/accessoryCartRepo.mjs`），功能四又往 `cart_items` 里以 `item_type='garment'` 写 `scene_catalog` 的 id（`server/repositories/sceneRepo.mjs:184`）——这些行在功能三的 `listCart` 里查不到对应 garment，会被 `.filter(Boolean)` 静默丢掉。规格 §13 只有一个 `cart_items` 数据域，§4.5 还要求「商品可以修改数量或删除」，而 `mall.vue:69` 的购物车图标至今是「功能开发中」。
3. **各功能内的零散差异**：§7.4 风格选项要求小图预览（现在是纯色块+emoji）、§7.9 3D 形象要求按身高体重体型呈现差异（现在只按性别换图）、§8.9 分享要求真实海报导出（现在 `outfit-result/index.vue:166` 只弹一句 toast）、§9.5 试戴背面无叠加。

本轮目标：把功能一、二、三做到能逐条对着规格 §7.10 / §8.12 / §9.9 打勾，并按模块分离产出交接文档。功能四~六不动（除购物车统一必须同步改的调用点）。

## 实施方案

### 批次 0A — 登录与演示账号（§5）

**后端**
- `server/schema.sql` + `server/db/mysql.mjs`：`users` 增 `account VARCHAR(64) NULL`、`password_hash VARCHAR(160) NULL`。沿用已有的 `ensureColumn(conn, table, name, ddl)`（`db/mysql.mjs:200`）做增量迁移，唯一索引查 `information_schema.STATISTICS` 后再建，避免重复执行报错。
- `server/services/authService.mjs`：新增 `passwordLogin(account, password)`（`node:crypto` scrypt + 随机 salt，存 `salt:hash`），`ensureDemoAccounts()` 幂等创建四类账号。复用现有 `findOrCreateByOpenid` / `setUserRole`（`repositories/userRepo.mjs`）。`adminLogin` 保留。
- `server/services/demoSeedService.mjs`（新）：给演示女性、演示男性账号灌真实衣橱、五步答案、画像、历史搭配、购物车、定制申请；空白账号只建号；管理员设 `role='admin'`。复用 `garmentService.ensureSeeded`、`profileRepo`、`outfitService.generateOutfits`。
- `server/routes/auth.mjs`：新增 `POST /login-password`、`GET /demo-accounts`（仅非 production 返回账号名，密码不下发）。现有 `/login`（微信）补 `isNewUser` 语义即可满足「首次注册、之后一键登录同一账号」。
- `server/index.mjs`：启动 `initDb()` 之后调用 `ensureDemoAccounts()`，与已有的 `ensureAccessories()` / `ensureSceneCatalog()` / `ensureDesigners()` 并列。
- `server/scripts/seedDemoAccounts.mjs` + `package.json` 加 `seed:demo`，满足 §15「比赛前可重置」。

**前端**
- 新增 `miniapp/src/pages/login/index.vue`：账号密码登录 + 微信一键注册/登录；`// #ifdef H5` 内显示演示账号选择器（§5.4），小程序端不暴露。
- 新增 `miniapp/src/api/auth.ts`、`miniapp/src/stores/auth.ts`（token / role / nickname / logout）。
- `miniapp/src/api/http.ts`：`ensureToken()` 不再自动建号——无 token 时抛 `NO_AUTH`，由调用方 `reLaunch` 到登录页；`dev-token` 仅保留为登录页上的开发按钮。
- `miniapp/src/App.vue`：启动检查 token，未登录 `reLaunch` 登录页。
- `miniapp/src/pages/me/me.vue`：`admin` 菜单先弹密码输入再调 `/api/auth/admin-login`（§5.3），另加「退出登录」。
- `miniapp/src/pages.json` 注册 `pages/login/index`。

### 批次 0B — 购物车统一（§4.4 §4.5 §13）

- `server/schema.sql`：`cart_items.item_type` 扩为 `ENUM('garment','accessory','catalog')`——`catalog` 用于商城/场景新品，修掉功能四把 `scene_catalog` id 当 garment 写入后查不出来的问题。
- `server/db/mysql.mjs` 新增 `migrateCart(conn)`：`MODIFY COLUMN` 扩枚举；把 `feature2_cart_items` 存量按 `INSERT ... SELECT ... ON DUPLICATE KEY UPDATE quantity = quantity + VALUES(quantity)` 搬进 `cart_items`；把已有 `item_type='garment'` 但 id 命中 `scene_catalog` 的行改判为 `catalog`。旧表保留不删，留回滚余地。
- `server/repositories/cartRepo.mjs` 重写为 `cart_items` 版本，`server/services/cartService.mjs` 吸收 `accessoryCartService` 的 `validateItem` 与 `hasOutfitInCart`，按三种 `item_type` 分别解析明细（garments / accessories / scene_catalog），越权一律 404。
- `server/routes/cart.mjs`：`GET /`、`POST /`、`POST /batch`、`POST /outfits/:id`、`PATCH /:id`、`DELETE /:id`。
- `server/services/accessoryCartService.mjs`、`server/repositories/accessoryCartRepo.mjs`、`server/routes/accessoryCart.mjs` 改成转发到统一 service 的薄层并标注弃用，保证 `scripts/checkAccessories.mjs:23` 与前端 `api/accessories.ts` 的 `/api/accessory-cart` 不断。`sceneRepo.addCatalogItemsToCart` / `listCart` 改走统一层。
- 前端新增 `miniapp/src/pages/cart/index.vue`（数量增减、删除、复制淘口令、来源搭配标记、搭配优惠提示）与 `miniapp/src/api/cart.ts`；`miniapp/src/stores/cart.ts` 由本地 id 数组改为真实后端购物车。入口接上 `mall.vue:69` 的购物车图标、`me.vue` 购物车统计、`accessory/index.vue` 购物车抽屉（抽屉内也加数量增减）。
