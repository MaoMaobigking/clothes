# AI 服装比赛原型：六功能需求规格与验收清单

> 版本：v0.1
> 日期：2026-08-13
> 状态：需求已逐项确认，待进入实现
> 适用项目：AI 服装比赛原型

## 1. 文档目的

本文档用于把六项功能从产品描述收敛为可开发和可验收的比赛原型需求。

本文档只描述“要做什么、做到什么程度、怎样算通过”，不负责具体代码实现。

## 2. 项目定位

### 2.1 目标

- 比赛演示原型，不按商业生产系统验收。
- 微信小程序优先，H5 作为开发预览和比赛备用入口。
- 核心目标是有完整演示闭环、真实数据驱动、AI 亮点可解释。

### 2.2 非目标

- 不接真实支付。
- 不接真实供应链、工厂、库存和物流。
- 不接真实人工客服。
- 不接真实手机 AR。
- 不抓取外部图片和内容。
- 不使用卡通图替代衣橱、商品、搭配等真实图片。

### 2.3 功能优先级

暂定优先级从高到低：

1. 个人身形创建与五步测试。
2. 旧衣上传与智能搭配。
3. 场景模拟与场景穿搭。
4. 配饰推荐与购买入口。
5. 差异化定制服务。
6. 时尚分享与穿搭教学。

## 3. 技术底座

### 3.1 目标技术架构

比赛版以微信云开发为主：

- 登录：云开发获取 `openid`，支持微信一键注册和登录。
- 数据：云数据库保存用户、画像、衣橱、搭配、订单、互动等数据。
- 图片和视频：云存储保存人工上传的真实素材。
- AI：云函数调用文本大模型。
- 当前 Node + MySQL 后端作为开发验证环境，不推翻已有代码，但需求字段按可迁移到云开发来设计。

### 3.2 平台

- 微信小程序为主要交付平台。
- H5 作为开发预览和备用演示入口。
- 小程序端不把“稳定拉起淘宝 App”作为验收项。

### 3.3 完成标准

按“可交互 MVP”验收：

- 核心用户闭环必须完整。
- 已有真实能力继续使用真实能力。
- 重能力允许使用明确标注的演示效果。
- 不把演示效果写成已实现的生产能力。

## 4. 公共业务规则

### 4.1 AI 真实度分层

| 层级 | 能力 | 本轮处理 |
|---|---|---|
| 真跑 | 个人风格报告、场景穿搭文字推荐 | 调用文本大模型，输出结构化结果 |
| 规则加真实数据 | 旧衣穿搭、配饰推荐 | 使用真实衣橱、画像、季节、场景和规则计算 |
| 演示模拟 | 衣物类型识别、3D 形象、AR 试戴、虚拟试衣 | 界面和交互真实，输入真实，效果使用稳定演示资源 |

所有 AI 结果必须能够解释输入来源，不能随机出现与当前用户无关的结果。

### 4.2 真实数据原则

以下数据必须真实保存：

- 用户画像。
- 五步测试答案。
- 风格报告。
- 用户衣橱和上传衣物。
- 搭配历史与模板。
- 购物车。
- 定制申请、聊天记录和演示进度。
- 社区互动、书签、笔记和学习成就。

以下过程只需现场演示，不要求每次操作永久留痕：

- AI 识别动画。
- 三套方案生成过程。
- 3D 试戴过程。
- 配饰推荐过程。
- 海报生成过程。

以下不做真实业务：

- 支付。
- 真实订单履约。
- 真实工厂生产。
- 真实人工客服。
- 真实实名认证。

### 4.3 图片资源规则

- 衣橱、商城商品、配饰、搭配方案、教程、社区内容统一使用人工上传的真实照片。
- 不联网抓图。
- 不生成卡通图。
- 用户上传的旧衣直接显示原始照片。
- 缺失图片时使用中性占位，不自动补卡通图。
- 图片先维护清单，再由人工按文件名和目录放入。

### 4.4 购买规则

- 商品数据必须包含淘宝链接和淘口令。
- 用户点击商品后弹出“正在前往淘宝……”提示，带跳转动画和“复制链接”按钮。
- 小程序端实际把淘口令写入剪贴板，提示用户打开淘宝查看。
- H5 端尝试打开淘宝链接，失败后复制淘口令。
- 不接微信支付，不做内部结算订单。

### 4.5 购物车规则

- 购物车按用户保存到数据库。
- 加入整套搭配时，拆成单品写入购物车，同时记录来源搭配。
- 商品可以修改数量或删除。
- 购物车不要求生成真实订单。
- 搭配优惠根据购物车中是否已有当前搭配服装计算。

## 5. 登录与演示账号

### 5.1 登录页面

打开小程序后先进入登录页，提供：

- 账号密码登录。
- 微信一键注册。

普通新用户第一次使用微信一键注册并自动登录。之后再次进入时使用微信一键登录回到同一账号，不再重复注册或输密码。

### 5.2 预置账号

预置四类账号，每类使用独立账号名和密码：

| 账号 | 用途 | 预置数据 |
|---|---|---|
| 演示女性账号 | 展示完整女性用户效果 | 完成五步测试、真实衣橱、历史搭配、购物车、定制申请 |
| 演示男性账号 | 展示不同性别和场景效果 | 完成画像、真实衣橱、场景搭配示例 |
| 空白新账号 | 演示从零开始的完整流程 | 无画像、无衣橱 |
| 管理员账号 | 查看数据看板和演示进度 | 管理员角色 |

### 5.3 管理员入口

- 管理员入口不在首页。
- 从“我的”页面进入管理员登录。
- 管理员使用独立密码登录。
- 登录后进入轻量管理员看板。

### 5.4 H5 兜底

- H5 备用入口可显示演示账号选择页。
- 正常微信小程序端不把账号选择器暴露给普通用户。

## 6. 全局信息架构

### 6.1 底部主导航

保持五个主 Tab：

- 首页。
- AI。
- 衣橱。
- 商城。
- 我的。

### 6.2 新增入口

- 个人身形创建从首页进入。
- 旧衣上传从衣橱或 AI 页进入。
- 配饰推荐从搭配方案进入，也可从商城或衣橱进入。
- 场景模拟从 AI 页或首页进入。
- 定制服务从首页或“我的”进入。
- 时尚社区从首页或 AI 页进入。

## 7. 功能一：个人身形创建

### 7.1 范围

完成五步测试、生成个人画像、生成风格报告和 3D 虚拟形象。

### 7.2 页面结构

拆成三个页面，但用户感知为一条连续流程：

1. 入口页：
   - 标题“开始你的专属穿搭之旅”。
   - 展示五步导览。
   - 提供开始按钮。
2. 五步测试页：
   - 顶部返回按钮和进度条。
   - 轮播式步骤引导。
   - 底部提供上一步、下一步、跳过。
3. 结果页：
   - 用户画像雷达图。
   - 3D 虚拟形象。
   - 保存并进入首页。

### 7.3 五步规则

| 步骤 | 选择方式 | 是否可跳过 |
|---|---|---|
| 风格 | 多选，最多 3 项，选满 3 项后才能下一步 | 不可跳过 |
| 肤色 | 单选 | 可跳过 |
| 脸型 | 单选 | 可跳过 |
| 体型 | 先选视觉体型，再填性别、身高、体重 | 不可跳过 |
| 偏好 | 5 道单选小问，至少答满 3 题 | 可跳过未答题 |

### 7.4 风格选项

- 休闲街头。
- 简约通勤。
- 法式浪漫。
- 韩系甜美。
- 复古优雅。
- 运动机能。

每个选项带真实或已配置的小图预览和简短描述。

### 7.5 体型信息

必填：

- 性别。
- 身高。
- 体重。
- 视觉体型选项。

可选：

- 胸围。
- 腰围。
- 臀围。
- 肩宽。
- 其他详细测量。

3D 虚拟形象使用已填数据生成，未填的细节使用中性默认值。

### 7.6 偏好题目

保留五道单选小问：

1. 买衣服最看重什么。
2. 最常穿的场景。
3. 色彩偏好。
4. 预算区间。
5. 版型偏好。

每题可以不答，但至少答满 3 题才能生成报告。

### 7.7 跳过与续做

- 风格和体型不可跳过。
- 肤色、脸型和偏好可跳过。
- 跳过的维度不硬塞默认答案，不参与对应雷达图评分。
- 结果页明确显示“该维度未完善”。
- 退出后重新进入时保留已填内容，支持继续完成。

### 7.8 报告生成

- 雷达图五个维度由用户真实答案和身体参数按规则计算。
- 风格报告正文调用文本大模型，输入为五步真实答案。
- AI 输出必须为结构化 JSON。
- AI 超时或失败时，使用规则生成基础版报告，并标明“基础规则版”。
- 测试答案和报告保存到数据库，用户可回看历史报告。

### 7.9 3D 虚拟形象

- 使用半写实 3D 人台或模特。
- 不使用卡通小人。
- 不要求上传真人脸。
- 按性别、身高、体重和体型呈现差异。
- 支持拖拽旋转、双指缩放、正面和背面切换。

### 7.10 功能一验收标准

- 能完整走完入口页、五步测试、结果页。
- 风格步骤未选满 3 项时不能进入下一步。
- 体型信息至少包含性别、身高、体重和视觉体型。
- 跳过维度在结果页可见。
- 报告和答案保存后重新打开仍存在。
- AI 失败时能看到基础规则版报告。
- 3D 形象可以旋转、缩放和切换视角。

## 8. 功能二：旧衣上传与智能搭配

### 8.1 范围

上传真实旧衣照片、整理衣橱、生成搭配方案、替换单品、保存历史。

### 8.2 上传规则

- 支持拍照和相册上传。
- 单次最多上传 20 张。
- 衣橱总量最多 100 件。
- 超出后提示先删除或整理。
- 上传图片必须为真实照片。

### 8.3 衣物识别

- 上传后显示“AI 识别中”动效。
- 给出类型、颜色、季节、场合等识别建议。
- 用户必须能够确认或手动修正。
- 修正后的标签写入该衣物。
- 比赛版识别过程允许使用稳定演示识别，不依赖容易现场失败的视觉模型。

### 8.4 衣物字段

每件衣物至少保存：

- 类型：上衣、下装、外套、连衣裙。
- 颜色：主色和辅助色。
- 季节：可多选。
- 场合：可多选。
- 是否“常穿”。
- 上传时间。

### 8.5 衣物整理区

- 网格展示缩略图。
- 支持拖拽排序。
- 支持删除。
- 支持标记“常穿”。
- 排序代表 AI 搭配优先权。
- “常穿”提高权重。
- 用户勾选参与搭配的衣物优先于普通衣物。

### 8.6 搭配生成

- 主按钮：“一键生成今日穿搭”。
- 副按钮：“手动调整搭配”。
- 默认最多使用最近上传或标记“常穿”的 30 件参与搭配。

### 8.7 手动调整

- 生成前：勾选参与搭配衣物，按类型筛选，查看已选清单。
- 生成后：点击任一单品，从同类库存中替换。
- 本轮不做复杂拖拽穿搭画布。

### 8.8 搭配结果页

- 保持左侧用户衣物列表、右侧 3 套搭配方案。
- 手机端左右双栏分别独立滚动。
- 每套方案包含全身效果图和单品拆解。
- 全身效果图使用当前真实衣物照片与统一模特或 3D 模板组合，不随机生成无关图片。

每套方案提供：

- 加入购物车。
- 收藏。
- 分享。
- 替换单品。

### 8.9 方案按钮行为

- 加入购物车：整套方案拆成单品写入用户购物车数据库。
- 收藏：保存到“我的搭配”，可回看。
- 分享：生成当前搭配海报，支持保存图片或微信分享。
- 替换单品：从当前用户真实衣橱中按同类替换，替换后立即刷新方案。

### 8.10 AI 算法说明浮层

- 展示当前实际参与衣物数量。
- 展示季节、场合、流行趋势等真实输入。
- 不使用与当前用户无关的固定文案。

### 8.11 历史搭配

- 在旧衣搭配页面提供“今日搭配 / 我的搭配”两个二级 Tab。
- 不增加第六个底部主导航。
- “我的搭配”显示收藏方案、生成时间和组成单品。
- 支持重新进入和分享。

### 8.12 功能二验收标准

- 能从相册上传多张真实照片。
- 识别建议可以被确认或修正。
- 衣橱支持排序、删除和常穿标记。
- 排序顺序确实影响生成方案。
- 结果页保持左右双栏并展示 3 套方案。
- 购物车数据保存后重新打开仍存在。
- 收藏和历史搭配可回看。
- 替换单品后方案立即更新。

## 9. 功能三：配饰推荐与购买入口

### 9.1 范围

基于当前服装推荐配饰、3D 虚拟试戴、评分、热门榜和淘宝购买入口。

### 9.2 入口和当前服装

- 从搭配方案点“去配配饰”，带当前方案进入。
- 也可从商城或衣橱进入，手动选择当前服装。
- 当前服装显示大图和标签。
- 没有服装时先引导选择服装。

### 9.3 配饰分类

严格保留五类：

- 首饰。
- 帽子。
- 围巾。
- 腰带。
- 鞋子。

每类展示 3 到 5 个推荐项。

### 9.4 推荐规则

- 根据当前服装类型、颜色、季节、场合和用户画像生成规则推荐。
- 每类最多展示 5 项。
- 排序依据匹配度、用户历史评分和热度。
- 每个推荐显示简短匹配理由。
- 没有匹配项时显示“可查看其他风格”，不随机推荐。

### 9.5 虚拟试戴

- 不接真实 AR。
- 在当前 3D 虚拟形象上叠加配饰。
- 支持旋转、缩放和正面背面切换。
- 有展示素材的配饰才能试戴。
- 没有素材时显示“暂无试戴素材”。

### 9.6 购买行为

- 点击配饰或商品后弹出“正在前往淘宝……”提示。
- 带跳转动画和“复制链接”按钮。
- 小程序端实际复制淘口令。
- H5 端尝试打开淘宝链接，失败后复制淘口令。
- 不接微信支付。

### 9.7 购物车与搭配优惠

- 配饰可加入购物车，按用户写入数据库。
- 购物车内商品可以复制淘口令。
- 若购物车包含当前搭配服装，配饰显示优惠价。
- 未包含时显示原价。

### 9.8 评分和热门榜

- 用户可对推荐配饰打 1 到 5 星。
- 评分按用户写入数据库。
- 推荐排序使用规则匹配度、当前用户历史评分和少量真实用户聚合评分。
- 热门搭配榜展示聚合评分和收藏最高的组合。
- 初始允许少量真实用户评分作为冷启动数据。

### 9.9 功能三验收标准

- 能从当前搭配进入配饰页。
- 五类配饰完整展示。
- 每项推荐有可解释的匹配理由。
- 3D 试戴在当前形象上可见。
- 点击商品出现淘宝跳转演示并复制淘口令。
- 购物车和评分保存后重新打开仍存在。
- 热门榜来自数据库中的真实互动数据。

## 10. 功能四：场景模拟与场景穿搭

### 10.1 范围

根据场景、真实定位、实时天气和用户衣橱生成旧衣方案与新旧混搭方案。

### 10.2 场景

- 日常休闲。
- 商务正装。
- 约会聚会。
- 旅行度假。
- 学院风。
- cosplay。

每个场景使用真实背景图和关键词标签。

### 10.3 生成输入

- 当前用户画像。
- 当前用户衣橱。
- 所选场景。
- 当前季节或用户选择季节。
- 实时地理位置。
- 实时天气。
- 仅用现有衣物或新旧混搭模式。

### 10.4 定位和天气

- 首次进入场景页时申请微信定位权限。
- 获取经纬度并查询真实城市、温度和天气状态。
- 生成结果显示“基于杭州 · 晴 · 28℃”这类来源。
- 用户拒绝授权或天气接口失败时，允许手动选择城市和天气。
- 获取失败不阻塞生成。

### 10.5 旧衣优先模式

- 提供“仅用现有衣物搭配”开关。
- 优先使用当前用户真实衣橱。
- 提示“已为你激活 XX 件旧衣，搭配出 3 套新造型”。

### 10.6 新旧混搭模式

- 系统先判断当前场景下衣橱缺少什么。
- 从人工维护的商城目录选择匹配新商品。
- 新商品必须有真实照片、价格和淘口令。
- 新增单品带“新增单品”标签。
- 支持旧衣与新衣方案对比。

### 10.7 方案效果图

- 每套方案展示全身效果图。
- 使用当前真实衣物照片与统一模特或 3D 模板组合。
- 不调用图片生成模型。
- 不随机使用与当前方案无关的衣服。

### 10.8 对比视图

- 同一场景生成纯旧衣方案和新旧混搭方案。
- 两版使用相同模特和场景背景。
- 支持左右并列或上下切换。
- 标注每版使用了哪些旧衣、新增了哪些单品。

### 10.9 场景滤镜

- 支持白天、夜晚、室内、户外等滤镜。
- 使用预设真实背景图和光影遮罩。
- 切换滤镜时衣服本身保持不变。
- 海报导出保留当前滤镜。

### 10.10 购买、保存和分享

- 一键购买全套：将新增单品加入购物车数据库，并列出各自淘口令复制按钮；旧衣不加入购买清单。
- 保存为模板：保存场景、天气、服装组合和历史版本，可在“我的搭配”重新打开。
- 分享场景：生成包含真实搭配、场景背景和滤镜的海报，支持保存或微信分享。

### 10.11 功能四验收标准

- 六个场景均可选择。
- 能读取或手动选择定位与天气。
- 能生成纯旧衣和新旧混搭方案。
- 新增单品来自真实商城目录并带淘口令。
- 滤镜切换即时且不影响服装选择。
- 对比视图清楚显示旧衣与新衣差异。
- 方案可保存、分享和加入购物车。

## 11. 功能五：差异化定制服务

### 11.1 范围

提供四类定制人群入口、定制咨询、预约量体、定制订单进度和设计师 IM。

### 11.2 人群分类

- 身材特殊人群：孕妇、肥胖、残疾等。
- 特殊场合需求者：团建、学院、演出等。
- 其他特定人群：coser、娃衣、高端消费者等。
- 追求独特品味者：设计师款、限量版等。

每类目包含：

- 图文介绍。
- 真实案例展示。
- 立即咨询入口。
- 预约量体裁衣入口。

### 11.3 定制流程

1. 选择服务类型。
2. 填写风格、颜色、面料、预算等需求。
3. 上传参考图。
4. 提交后查看设计师沟通和定制进度。

### 11.4 咨询表单

- “立即咨询”打开预填服务类型的表单。
- 表单包含需求、尺码、预算和参考图。
- 提交后保存到数据库。
- 页面显示“已提交，设计师将尽快联系”。
- 不接真实人工客服。

### 11.5 预约量体裁衣

必填：

- 身高。
- 体重。
- 胸围。
- 腰围。
- 臀围。
- 肩宽。

必传：

- 正面全身照。
- 侧面全身照。

可选：

- 后视图。
- 细节图。
- 特殊体态说明。

上传照片使用用户真实照片，数据保存到定制申请记录。

### 11.6 定制订单和进度

- 用户提交后创建一条用户级定制申请记录。
- 记录保存需求、参考图、聊天记录和进度。
- 状态包括：
  - 已提交。
  - 设计稿。
  - 打样。
  - 生产中。
  - 发货。
- 不接真实付款和工厂生产。

### 11.7 设计师一对一 IM

- 使用应用内 IM，不跳转微信。
- 消息写入数据库，用户可回看历史。
- 设计师为系统自动设计师，不依赖真实人员在线。
- 系统根据当前定制需求生成确认风格、面料、工期等回复。
- 预置少量设计师账号。

### 11.8 高端定制与 VIP

- 展示明星同款、手工刺绣、限量联名等真实案例。
- 演示账号预置不同会员等级。
- VIP 预约校验当前用户等级。
- 不接真实身份证和人脸认证。
- 未达标时显示升级演示弹窗。

### 11.9 功能五验收标准

- 四类人群可以进入各自详情页。
- 咨询表单提交后保存并可见提交状态。
- 量体预约能上传真实照片和尺寸。
- 定制申请能创建并显示进度。
- 内置 IM 可发送消息、收到设计师回复并回看。
- VIP 限制按演示会员等级生效。

## 12. 功能六：时尚分享与穿搭教学

### 12.1 范围

提供杂志、教程、用户分享、话题挑战和学习成就。

### 12.2 页面导航

时尚社区页顶部保留四个 Tab：

- 杂志推送。
- 穿搭教程。
- 用户分享。
- 话题挑战。

不增加第六个底部主导航。

### 12.3 内容来源

- 杂志、教程、用户内容全部由人工准备并放入项目。
- 使用真实照片和真实视频。
- 不联网抓取。
- 不生成卡通图。
- 预置少量真实测试用户和内容，支撑互动演示。

### 12.4 杂志推送

- 类 Vogue 电子版封面流。
- 每月更新。
- 支持离线下载。
- 支持放大阅读。
- 支持书签。
- 支持笔记。
- 书签和笔记按用户保存到数据库。
- 离线下载保存内容、图片地址和阅读进度到本地。
- 不要求缓存完整视频。

### 12.5 穿搭教程

分类：

- 新手入门。
- 高级技巧。
- 场景穿搭。
- 配饰搭配。

内容采用视频和图文混合排版。

跟练模式：

- 使用真实视频播放器。
- 显示分段步骤。
- 点击步骤暂停视频。
- 展示对应文字说明和穿搭图。
- 不接摄像头识别用户动作。

### 12.6 用户分享

- 瀑布流展示穿搭照片。
- 支持点赞、评论、收藏、举报。
- 支持热门话题标签。
- 互动按用户写入数据库。
- 点赞计数真实变化。
- 评论其他演示账号和当前用户可见。
- 收藏进入“我的收藏”。
- 举报后标记内容，当前用户不再看到。
- 本轮不接人工审核后台。

### 12.7 学习成就

- 完成教程获得积分和徽章。
- 成就和积分按用户保存到数据库。
- 教程详情显示完成状态。
- 个人中心展示已获徽章和学习进度。

### 12.8 博主合作

- 预置少量认证博主。
- 展示博主独家教程和合作入口。
- 不接真实签约、收益结算和博主实名审核。

### 12.9 管理员数据看板

- 使用轻量管理员页面。
- 展示真实统计：
  - 用户数。
  - 内容数。
  - 点赞、评论、收藏数。
  - 教程完成数。
  - 热门话题。
- 数据来自云数据库中的实际记录。
- 本轮不做专业漏斗、留存率和复杂 BI。

### 12.10 功能六验收标准

- 四个顶部 Tab 可用。
- 杂志可放大、书签、笔记和离线查看。
- 教程可播放并按步骤暂停。
- 用户分享可以上传真实照片并互动。
- 学习徽章和积分真实累计。
- 管理员看板读取真实数据库统计。

## 13. 核心数据实体

目标云数据库至少覆盖以下数据域：

| 数据域 | 说明 |
|---|---|
| users | 微信 openid、昵称、头像、角色、可选密码哈希 |
| body_profiles | 五步测试答案、体型数据 |
| style_reports | 测试答案、AI 结构化报告、时间 |
| garments | 用户衣橱、字段、排序、常穿状态 |
| outfits | 搭配方案和模板 |
| outfit_items | 方案中的衣物组成 |
| accessories | 配饰目录、评分、试戴素材、淘口令 |
| cart_items | 用户购物车单品和来源 |
| custom_requests | 定制申请、参考图、状态 |
| chat_messages | 设计师 IM 消息 |
| contents | 杂志、教程、用户分享和话题 |
| interactions | 点赞、评论、收藏、举报 |
| achievements | 用户积分和徽章 |

所有用户数据必须按当前用户隔离，不能读取其他普通用户数据。

## 14. 图片清单与上传规范

先产出图片清单，包含：

- 文件名。
- 用途。
- 建议尺寸。
- 存放目录。
- 是否需要淘口令。

建议默认格式：

- 照片：JPEG、PNG 或 WebP。
- 封面建议比例：1:1 或 4:3。
- 视频：MP4。

具体文件大小限制在实现前根据云存储额度再确定。

缺失素材时显示中性占位，不使用卡通图替代。

## 15. 现场演示原则

- 核心链路优先保证稳定，不依赖容易失败的网络模型。
- 所有真实 AI 调用必须有失败提示或兜底。
- 定位、天气、AI、淘口令缺失时不能阻塞整页。
- 演示账号数据提前准备并可在比赛前重置。
- 预置数据与空白账号都要可演示。

- 不接真实 AR。
- 不接真实人工客服。
- 不接真实工厂订单。
- 不接真实实名认证。
- 不做完整管理后台。
- 不做专业 BI 和复杂用户分析。
