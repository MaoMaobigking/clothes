```

├── repositories/      ← 只碰数据库（CRUD 原子操作）
│   ├── garmentRepo.mjs
│   ├── userRepo.mjs
│   └── aiRepo.mjs
└── db.mjs             ← 数据库连接池（MySQL） + 初始化建表
```

### 2.2 SQLite → MySQL ⏳

- [ ] **2.2.1** 本地装 MySQL（或 Docker：`docker run -d -p 3306:3306 -e MYSQL_ROOT_PASSWORD=... mysql:8`）
- [ ] **2.2.2** 创建数据库 `lingxi` + 建 7 张表：

```sql
-- users
CREATE TABLE users (
  id INT AUTO_INCREMENT PRIMARY KEY,
  openid VARCHAR(64) UNIQUE,
  nickname VARCHAR(64),
  avatar_url VARCHAR(512),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- body_profiles  身形档案
CREATE TABLE body_profiles (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NOT NULL,
  skin VARCHAR(32),          -- 肤色
  face VARCHAR(32),          -- 脸型
  body_type VARCHAR(32),     -- 体型
  height DECIMAL(5,1),
  weight DECIMAL(5,1),
  bmi DECIMAL(4,1),
  bust DECIMAL(5,1),
  waist DECIMAL(5,1),
  thigh DECIMAL(5,1),
  calf DECIMAL(5,1),
  preferences JSON,          -- 偏好
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id)
);

-- ★ style_reports  AI 风格报告
CREATE TABLE style_reports (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NOT NULL,
  answers JSON,              -- 测试答案
  result JSON,               -- AI 分析结果 (summary/radar/palette/recommendations/tips)
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id)
);

-- garments  衣橱
CREATE TABLE garments (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NOT NULL,
  name VARCHAR(128) NOT NULL,
  category VARCHAR(32),
  color VARCHAR(32),
  image_url VARCHAR(512),
  is_fav BOOLEAN DEFAULT FALSE,
  brand VARCHAR(64),
  season VARCHAR(32),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id),
  INDEX idx_user_id (user_id)
);

-- outfits  搭配方案
CREATE TABLE outfits (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NOT NULL,
  title VARCHAR(128),
  scene VARCHAR(32),
  reason TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id)
);

-- outfit_items  搭配含哪几件衣服
CREATE TABLE outfit_items (
  id INT AUTO_INCREMENT PRIMARY KEY,
  outfit_id INT NOT NULL,
  garment_id INT NOT NULL,
  sort_order INT DEFAULT 0,
  FOREIGN KEY (outfit_id) REFERENCES outfits(id) ON DELETE CASCADE,
  FOREIGN KEY (garment_id) REFERENCES garments(id)
);

-- ★ chat_sessions  AI 顾问会话
CREATE TABLE chat_sessions (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NOT NULL,
  title VARCHAR(128),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id)
);

-- ★ chat_messages  每条消息
CREATE TABLE chat_messages (
  id INT AUTO_INCREMENT PRIMARY KEY,
  session_id INT NOT NULL,
  role ENUM('user','assistant') NOT NULL,
  content TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (session_id) REFERENCES chat_sessions(id) ON DELETE CASCADE,
  INDEX idx_session_id (session_id)
);
```

- [ ] **2.2.3** 把 `server/db.mjs` 从 `node:sqlite` 改为 `mysql2`（连接池）

- [ ] **2.2.5** 验证：所有衣橱 CRUD 走 MySQL 正常

**验收**：MySQL 7 张表建好，衣橱 CRUD 可跑，旧数据不丢。

### 2.3 JWT 登录 + 越权控制 ⏳

## 🔴 阶段三 · AI 工程化核心（蓝图步骤 3）★上限所在

> **目标**：从「调了个 AI 接口」升级到「做过 AI 工程」。按序做，每个都是一个面试故事。
> **当前状态**：`server/index.mjs` 有 3 个 AI 接口（风格报告/情景推荐/对话），但都只是普通的 HTTP 调大模型。

### 3.1 结构化输出 ⏳

- [ ] **3.1.1** 用 JSON Schema 约束风格报告输出（不用 prompt 里喊"只返回 JSON"）
  - OpenAI：`response_format: { type: "json_schema", json_schema: {...} }`
  - Anthropic：用 tool_use / `response_format` 新版 API
  - 兜底：手写 JSON 提取 + Schema 校验（ajv）
- [ ] **3.1.2** 结果校验后写入 `style_reports` 表
- [ ] **3.1.3** 前端展示：从数据库读历史报告，不是每次重新生成

**面试话术**："我用 JSON Schema 约束模型输出，前端可以稳定解析，不是靠 prompt 祈祷模型不乱写。校验失败的自动重试。"

### 3.2 流式输出 (SSE) ⏳

- [ ] **3.2.1** AI 顾问对话接口改为 SSE（Server-Sent Events）
  - `POST /api/chat/stream` → 响应头 `text/event-stream`
  - 逐 chunk 推给前端，格式 `data: {"delta":"...","done":false}\n\n`
- [ ] **3.2.2** 前端：打字机效果渲染（逐字显示）
- [ ] **3.2.3** 流式结束后保存完整消息到 `chat_messages`
- [ ] **3.2.4** 支持中途停止（前端 abort → 后端清理）

**面试话术**："我做了 SSE 流式输出，首字延迟低、体验好。前端逐字渲染，支持中途停止。流式结束后完整消息存库，下次进来能看历史。"

### 3.3 工具调用 / Function Calling（手写） ⏳

- [ ] **3.3.1** 定义工具集（至少 3 个）：
  ```js
  const tools = [
    { name: 'search_garments', description: '搜索用户衣橱', parameters: { query, category, color } },
    { name: 'get_weather', description: '查询城市天气', parameters: { city } },
    { name: 'get_user_profile', description: '获取用户身形/风格偏好', parameters: {} },
  ]
  ```
- [ ] **3.3.2** 手写 tool-calling 循环：
  ```
  用户消息 → 拼 tools → 调模型 → 
    模型返回 tool_calls？→ 执行工具 → 结果喂回模型 → 
    模型返回 text？→ 流式输出给用户 → 结束
  ```
- [ ] **3.3.3** 对话接口集成（AI 顾问聊天时可自动查衣橱/天气推荐）
- [ ] **3.3.4** 场景搭配也走工具调用（查天气 → 查衣橱 → 推荐）

**面试话术**："我手写了 tool-calling 循环，不是调的 SDK 封装。流程是：用户问→模型决定要不要调工具→我执行→结果喂回→模型最终回复。比如用户问'明天上班穿什么'，AI 先调查天气再看衣橱，最后综合推荐。"

**阶段三完成标志**：至少完成 3.1+3.2（最低目标），3.3 做完差异化就够。每个能力都有独立 API 可演示。
