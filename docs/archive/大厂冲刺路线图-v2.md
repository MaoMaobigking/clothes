## 一、现状诚实盘点

monorepo `ai-fashion-studio`,5 个子项目:

| 模块 | 是什么 | 完成度 | 能亲口讲清吗 | 现状要害 |
|---|---|---|---|---|
| **server**(Node Express) | 真后端:AI+RAG+MCP+JWT | ★★★★☆ 能跑 | ✅ 全 JS | 用户隔离/持久化/登录是假的;MCP 工具写死且没接进产品 |
| **web**(Vue3 H5) | C 端主界面 | ★★★★☆ 能跑 | ✅ 强项 | 只接了非流式对话,SSE/工具/RAG 前端没用上 |
| **miniapp**(uni-app) | 小程序,web 的跨端翻版 | ★★★☆☆ H5能跑 | ✅ 全 Vue | 无图 / 小程序端接口连不上 / 有崩溃 bug |
| **admin**(Element Plus) | B 端后台 | ★★☆☆☆ 空壳 | ✅ 强项但薄 | 假数据 / 假登录(账密写死源码)/ 没连后端 |
| **ai-server**(Python) | AI 后端,Node 的翻版 | ★★☆☆☆ 跑不起来 | ❌ 不会 Python | 开箱报错 / 和 Node 完全重复 / 没接线 |
| 工程化 | git/CI/测试/Docker | ★☆☆☆☆ 几乎没有 | — | 连 git 仓库都还没建 |

**当前真正在跑的 AI 大脑 = Node `server/`(用 DeepSeek)**,前端全走它;Python 那套是并行僵尸副本。

## 二、核心诊断

冲击大厂,这个项目的病**不是功能少,而是"虚"**:摊子太大、一半是壳、还有一块(Python)讲不了。大厂面试官必定**深挖**("MCP 现场调一个""登录鉴权怎么做""为什么两个后端"),一挖壳就碎。

> `docs/项目升级技术文档.md` 里你自己已经诚实写过("玩具感来源""看起来有其实是壳")——心里有数,现在动手治。

**战略转向:从"往上堆功能" → "收敛摊子 + 把壳做成真 + 全部变成能亲口讲的"。**

---

## 三、锁定的战略与决策(2026-07-21 已拍板)

- **主线** = `web`(Vue3 H5) + `server`(Node Express)。做深做实做到戳不穿。
- **Python `ai-server`** = 如实标注为"练手翻译版 / 实验分支",**不投入、不进主线故事**。
- **后端框架** = **保留 Express,不重写 NestJS**。把现有的壳补成真,省时间、先能讲。(NestJS 留作秋招前若有余力的可选升级。)
- **miniapp / admin** = 降级为附加/原型,主线故事不依赖它们(admin 见"拔高层"可被 AI 监控台救活)。
