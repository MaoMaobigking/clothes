# 微信云托管部署 —— 从零到体验版二维码

你没有云服务器，所以走这条路：**云托管 = 微信替你跑容器 + 送一个免备案的 HTTPS 域名**，
全程在网页上点，不碰 Linux、不装 pm2、不配 Nginx、不备案域名。

后端和那 139 张演示图跑在**同一个容器**里，前端一行代码不用改。

不是纸上谈兵，下面这些是在本机 Docker 里真跑过的（2026-08-18）：

| --- | --- |

> 这两条任意一条不通，立刻告诉我，我转回「买台最便宜的云服务器」方案，

## 3. 建 MySQL

云托管控制台 → **数据库** → MySQL → 新建实例：

- 规格挑**最小的**，演示够用
- 设一个 root 密码，**记下来**
- 创建要等 5~10 分钟

建好之后记下三个值：

- **内网地址**（形如 `10.x.x.x`，不是公网地址）
- 端口，通常 `3306`
- root 密码

**不用手动建库。** `server/schema.sql` 第一行就是 `CREATE DATABASE IF NOT EXISTS lingxi`，
容器启动时 `initDb()` 会自己执行，表也一起建好。

> 但库名必须保持 `lingxi` —— schema.sql 里是写死的，改 `MYSQL_DATABASE` 会对不上。

## 5. 建服务并部署

云托管控制台 → **服务管理** → 新建服务：

| 字段 | 填什么 |
| --- | --- |
| 服务名 | `api` |
| 端口 | **80** |
| 部署方式 | 本地代码上传 |
| 代码包 | `deploy/dist/cloudrun.zip` |
| Dockerfile 路径 | `Dockerfile` |
| 最小副本数 | `1`（填 0 会缩容到零，客户扫码时要等冷启动十几秒） |

### 环境变量

打开 `deploy/dist/云托管环境变量.txt`，逐条粘进控制台的环境变量面板。
里面 AI 的 key、JWT 密钥都已经从你本机 `server/.env` 抄好了，**只有这五项要你自己改**：

```ini
MYSQL_HOST=      ← 第 3 步的内网地址，【只填地址，不要带 :3306】
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=  ← 第 3 步的 root 密码
MYSQL_DATABASE=lingxi
PORT=80
```

> ⚠️ **`PORT` 和 `MYSQL_PORT` 是两回事，最容易填串**：
> `PORT=80` 是服务自己监听的端口（云托管按它探活），`MYSQL_PORT=3306` 是数据库的端口。
> 把 `MYSQL_PORT` 也填成 80，容器就是在连自己，报 connection refused。
>
> 另一个常见错是把控制台上的「内网地址」连端口一起粘进 `MYSQL_HOST`，
> 变成 `10.x.x.x:3306`。报错会是 `getaddrinfo EAI_AGAIN 10.x.x.x:3306`，
> 看着像 DNS 挂了，其实是整串被当成域名去解析了。
>
> 这两条现在代码都会在连库之前查出来并打成 `⚠️ 数据库配置：...`
> （见 [server/db/mysql.mjs](../server/db/mysql.mjs) 的 `resolveDbConfig`），
> 带端口的 host 还会自动拆开。但别指望它兜底，照上面填就对了。
>
> 为什么脚本要把这几项换成占位符而不是照抄：你本机是 `localhost:3308` 的 docker 容器，
> 原样搬上去必然连不上。而 [server/index.mjs:121-144](../server/index.mjs#L121-L144) 是
> **连不上库就 `process.exit(1)`**，表现成「部署一直失败、容器反复重启」，
> 日志里还看不出是数据库的锅 —— 这是这条路最容易卡死的一步，直接堵掉。

点部署，等它 build 镜像（5~15 分钟，看网速）。

### 怎么算成功

去看服务日志，出现这几行就是好了：

```
✅ MySQL 已连接并建表: 10.x.x.x:3306/lingxi
✅ 配饰目录已初始化: 18 件
✅ 场景商城目录已初始化
✅ 演示账号已就绪: 4/4
✅ AI 后端已启动: http://localhost:80
```

如果反复看到 `❌ MySQL 连接失败` → 回第 3 步核对内网地址和密码。

### 构建就失败，连服务日志都没有

先分清是**哪一段**挂的。发布流水线那几行状态（`create_build_image` /
`check_build_image`）只告诉你成败，真正的报错在
**服务 → 版本列表 → 点那个版本 → 「构建日志」**（不是「服务日志」）。

关键判据是构建日志里**有没有 `Step 1/N`（或 buildkit 的 `#5 [1/8] FROM ...`）**：

| 现象 | 说明 | 怎么办 |
| --- | --- | --- |
| 一行 `Step` 都没有，几十秒内就 fail | 还没开始跑 Dockerfile | 见下面两条 |
| 卡在某个 `Step` 上失败 | 真跑起来了 | 照那一步的报错处理 |

没开始跑 Dockerfile，就两种可能：

1. **拉不到基础镜像**。日志里是 `failed to solve` / `i/o timeout` /
   `pull access denied` 之类。云托管构建机拉 Docker Hub 会偶发超时。
   改 [deploy/Dockerfile](Dockerfile) 里那行 `ARG NODE_IMAGE=`，换成
   `mirror.ccs.tencentyun.com/library/node:20-alpine`（腾讯云的 Docker Hub 镜像源，
   只在腾讯云网内可达，所以换了之后本机就没法 `docker build` 验证了）。
2. **控制台的「Dockerfile 路径 / 构建目录」填错**。用云托管的 express 之类模板建服务时
   这两项会被预填成模板仓库的布局（常见 `container/Dockerfile`），换成本地代码上传后
   得手动改回：Dockerfile 路径 `Dockerfile`、构建目录 `/`。

> 构建期只有一个外网依赖（拉基础镜像）。原来还有一个 `apk add tzdata`，
> 已经删了 —— Node 20 自带 full-icu，时区不读系统 zoneinfo，只给 `TZ` 就是 `+0800`，
> 那层纯粹是白送一个能让构建挂掉的理由。

## 6. 开公网访问，拿域名

服务详情 → **访问方式** / 公网访问 → 开启，会给你一个域名，形如

```
https://api-<环境ID>.ap-shanghai.run.tcloudbase.com
```

**立刻用浏览器验证两条**（这一步花 10 秒，能省掉后面一堆瞎猜）：

1. 打开 `https://你的域名/` → 应该看到 `{"ok":true,"service":"ai-fashion-server"}`
2. 打开 `https://你的域名/images/closet/g1.jpg` → 应该看到一张衣服图

两条都过了，后端就彻底没问题了。

## 7. 把域名加进小程序的白名单

<https://mp.weixin.qq.com> → 开发管理 → 开发设置 → **服务器域名**：

- **request 合法域名**：加上你的云托管域名
- **uploadFile 合法域名**：也加上（衣橱上传图、AI 试衣要用）

> 这个域名是腾讯签发的，**不需要备案**，直接能加。
> `<image src>` 不受这个白名单管，所以图片其实不加也能显示，但接口必须加。

## 8. 填打包配置

编辑 `miniapp/.env.production`（已 gitignore），把域名填进去：

```ini
VITE_CLOUD_ENV=
VITE_API_BASE_URL=https://你的域名
VITE_CLOUD_IMG_BASE=https://你的域名/images
```

三条各管一件事：

- `VITE_CLOUD_ENV` **留空** —— 空 = 关掉云开发那条链路，前端直连域名，
  `cloudfunctions/` 整个用不上了（留着不碍事）
- `VITE_API_BASE_URL` —— 接口地址，[miniapp/src/api/http.ts:25](../miniapp/src/api/http.ts#L25) 读它
- `VITE_CLOUD_IMG_BASE` —— 图片前缀。编译期把源码里的 `/static/images/xxx` 换成
  `https://域名/images/xxx`，运行期 [api/cloud.ts:165](../miniapp/src/api/cloud.ts#L165)
  再把接口返回的那 78 条路径也换掉

## 9. 打包、上传、出二维码

```bash
npm run mp:build:cloud
```

这条命令 = `uni build -p mp-weixin` + `scripts/pack-mp.mjs`。后者会：
删掉产物里没人引用的 3.2 MB 静态图、报最终主包体积。
**如果它报「产物里还留着 /static/images 引用」就停下来找我** ——
那说明第 8 步的 `VITE_CLOUD_IMG_BASE` 没生效，硬传上去的结果是真机上图全裂。

然后：

1. 微信开发者工具 → 导入项目 → 目录选 `miniapp/dist/build/mp-weixin`
2. 右上角 **上传** → 填个版本号
3. <https://mp.weixin.qq.com> → 管理 → 版本管理 → 把刚传的版本**设为体验版**
4. 同一页面会出体验版二维码，把它发给客户

docker rm -f aif-app aif-mysql && docker network rm aif   # 收工清理
