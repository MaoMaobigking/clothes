# UI 按设计稿对齐 + 样式集中管理

> 日期：2026-08-17　依据：用户提供的 8 张设计稿、`docs/开发手册.md` §3 §4

## 一句话

把全站 404 处 emoji 换成线性图标、缺图占位去卡通化，并把散在 58 个文件里的
8900 行样式收敛出一套集中管理的设计系统（`miniapp/src/styles/` 三个文件）。

## 为什么这批必须做

用户给了 8 张设计稿要求对齐。第一轮只改了 3 个页面就交付，用户在小程序里
看到的仍是「一堆 emoji + 卡通按钮」，明确否决了分批试点：

> 页面结构布局和样式我都已经发你了 就按那个改 怎么页面还是一堆emoji
> 按钮什么的都是卡通 你用过淘宝和京东吗 哪有这么多卡通

之后又指出两个问题，都成立：

> 还有"个性化创建这种"为什么一定要有图标卡片？
> 我觉得ui越改越乱 有覆盖重叠的问题 你能把ui组件整理好吗

「卡通感」的三个来源：emoji 当图标、缺图占位是「彩色渐变块 + 3D emoji」、
文案里塞 emoji。设计稿的语言是**照片驱动**，图标只在导航/分类出现且很小。

## 改了什么

### 图标体系（新增）

- `miniapp/src/utils/icons.ts` —— 92 个线性图标的 path 表 + `iconForEmoji()` 映射
- `miniapp/src/components/UiIcon/UiIcon.vue` —— 运行时拼 SVG → base64 → `background-image`

**`iconForEmoji` 是这批的关键设计**：全站 20+ 处调用点仍在传 `emoji="🧥"`，
`TileImage` / `OptionCard` 自动查表转成线条图标，调用点一行没改，
数据层 247 处 emoji 一次性全转。

### 去卡通化

- `TileImage`：缺图占位从「彩色渐变 + 大 emoji」改成中性浅灰 + 细线图标
- `OptionCard`：有 emoji 的选项（风格/脸型/体型）走中性底；**肤色选项没有 emoji，
  它的 `color` 是真实肤色色卡，必须原样保留**
- create / free-match 右侧工具栏去掉白色卡片外壳（设计稿是裸图标 + 文字）
- 首页九宫格去掉图标色块
- 文案里的 emoji 全删

### 排版对齐设计稿

- 个性化创建（图①）：基础信息面板 330→288rpx、单行化、五步测试缩小
- 我的衣橱（图③）：**左侧竖排分类栏 + 右侧两列网格**；标题「旧衣新穿」→「我的衣橱」；
  分类数据源 `WARDROBE_CATEGORIES`（9 项无「全部」）→ `CLOSET_CATEGORIES`（10 项，
  key 与接口一致所以筛选逻辑没动）

### 样式集中（新增 `miniapp/src/styles/`）

| 文件 | 内容 |
|---|---|
| `tokens.css` | 颜色 / 渐变 / 圆角 / 阴影 / 间距 / **z-index 层级** |
| `base.css` | `.page` `.page-stage` `.body` 骨架、滚动、横滑 |
| `components.css` | `.btn` `.card` `.chip` `.empty` `.mask` `.sheet` `.toast` `.grid-2` |

App.vue 用 `@import` 引入（小程序 WXSS 支持 `@import`，已验证编译进 `app.wxss`）。

### 顺带修掉的现存 bug

1. **`TileImage` 的 `ratio` 从未生效** —— prop 声明了没接到样式上，`<image>` 绝对定位
   不撑高，一传 `src` 图片就渲染成 0 高。20 个文件受影响，磁盘上长期只有 2 张图所以没暴露。
   改用 padding-top 撑开（不用 `aspect-ratio`，小程序低版本不支持）。
2. **`ai` / `closet` / `mall` 三个 tab 页双标题** —— 页面按自定义导航写的（有
   `env(safe-area-inset-top)`），`pages.json` 却没声明 `navigationStyle: custom`。
3. **free-match 底部 chips 竖排** —— `display:flex` 加在 `scroll-view` 外层，
   uni-app 的内容其实在内层容器，flex 传不下去。
4. **closet 生成卡文字重叠** —— 「手动调整搭配」用 `position:absolute` + `bottom`，
   卡片高度由上面的标题撑开，两者必然叠。

## 五个不显然的坑（改之前请先读）

### 1. 非组件模块不能放在 `components/<X>/` 下

`icons.ts` 最初放在 `components/UiIcon/icons.ts`，微信开发者工具报
`module 'components/UiIcon/icons.js' is not defined` 并**整站白屏**。
文件在磁盘上、语法合法、require 路径正确、`packOptions.ignore` 为空、
没有 `lazyCodeLoading` —— 是工具没把新建组件目录里的**普通模块**纳入注册表
（同目录的 `UiIcon.js` 因为被 `usingComponents` 声明过反而正常加载）。
移到 `utils/icons.ts` 后解决。**共享模块一律放 `utils/` 或 `data/`。**

### 2. z-index 必须走变量，不能手写数字

重构前 `.toast` 在 8 个页面分别写了 10 / 40 / 50 / 60，`.mask` 写了 20 / 30 / 40 / 50。
z-index=10 的提示会被别处 z-index=20 的遮罩盖住 —— 这是用户说的「覆盖重叠」的真因。
现在统一 `--z-raised(2) → float(10) → sticky(20) → mask(100) → sheet(110) → toast(200)`，
提示永远最高。

### 3. 全局 `.page` 必须同时写 `height:100%` 和 `min-height:100vh`

只写 `100%`：父链（`uni-page-body`）没有确定高度时解析不出来，页面缩成内容高度，
底部导航跑到屏幕中间、绝对定位浮层互相重叠（迁移过程中 create 页就这么塌过）。
只写 `100vh`：内容超出一屏时高度被钉死，内部 flex 滚动区算不对。

### 4. scoped 规则不删掉，全局样式永远不生效

scoped CSS 编译成 `.mask[data-v-xxx]`，优先级高于全局 `.mask`。
所以「加了全局类」不等于生效，必须删掉页面里的重复定义 ——
这是 `scripts/css-migrate.mjs` 存在的原因。

### 5. 项目文件是 CRLF，脚本里用 `'...\n'` 做替换会静默失效

`String.replace` 不匹配时返回原串、不报错，脚本还会显示"成功"。
批量改文件的脚本要用 `/\r?\n/` 或先探测行尾。

## 环境与复现

```bash
# H5 预览 + 截图（后端不必启动，脚本会把 /api/ 打桩成 503）
cd miniapp && npm run dev:h5
node scripts/ui-shot.mjs                 # 全部页面
node scripts/ui-shot.mjs home closet     # 指定页面

# 小程序：project.config.json 的 miniprogramRoot 指向 dist/build/mp-weixin
cd miniapp && npm run build:mp-weixin    # 必须是 build，不是 dev
```

> ⚠️ 跑 `dev:mp-weixin` 产物落在 `dist/dev/`，开发者工具根本不看那里，
> 会一直显示旧版本 —— 排查「改了没反应」先确认这条。

> ⚠️ `ui-shot.mjs` 的路由拦截必须用 `url.pathname.startsWith('/api/')`。
> 写成 glob `**/api/**` 会把 `/src/api/http.ts` 这些**应用源码**也拦掉，整页白屏；
> 拦截要用 `fulfill(503)` 不能 `abort`，abort 会让 `networkidle` 永不满足、
> goto 超时截到空白页。
