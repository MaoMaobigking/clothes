# 功能四实现与浏览器验收

- **模块**：功能四 · 场景模拟与场景穿搭
- **日期**：2026-08-14
- **分支**：codex/feature-4-scene-simulation
- **状态**：已完成，待真实图片素材
- **一句话**：实现六场景选择、定位/手动天气、纯旧衣与新旧混搭、场景滤镜、对比视图、保存模板、分享/海报、淘口令购买与购物车落库，并通过 H5、小程序构建和浏览器点击验收。

## 任务与范围

按 `docs/六功能需求规格与验收清单.md` 第 10 章完成功能四，不扩展功能一至三、五、六。

已完成：

- 六个场景：日常休闲、商务正装、约会聚会、旅行度假、学院风、cosplay。
- 定位天气：首次进入请求定位，后端可选 OpenWeather 真实天气；失败自动降级或手动选择，不阻塞生成。
- 方案生成：后端读取本人画像和衣橱，按场景槽位/季节生成 3 套纯旧衣和 3 套新旧混搭。
- 新旧混搭：从人工维护的 `scene_catalog` 补缺槽，新品带价格、淘口令和“新增单品”标签。
- 滤镜：白天、夜晚、室内、户外，只改变舞台背景/光影，不改变衣服组合。
- 对比视图：同一场景同时展示纯旧衣与新旧混搭，两版使用同一场景背景和模特图。
- 保存模板：`scene_outfits` 按用户隔离，新增“我的搭配”列表页可重新打开。
- 分享与海报：复制分享文案、微信 share 配置、Canvas 海报保存；H5 不支持保存时回退复制文案。
- 购买：只把新品写入 `cart_items`，展示对应淘口令复制按钮，旧衣不加入购物车。

明确未做：

- 不生成真实商品/场景照片，当前 `scene-catalog.json` 和 `scene.ts` 的图片路径是待人工填充的占位路径。
- 不接真实支付、真实淘宝跳转或工厂订单。
- 不在本轮实现 AI 图片生成、真实 3D 试穿和人工客服。

### Node 后端

- `server/scene-catalog.json`
  - 人工维护场景商城目录，每件商品包含分类、价格、图片占位路径、淘口令。

- `server/scripts/checkScene.mjs`
  - 数据层验收脚本：六场景、方案规则、模板隔离、购物车落库。
- `server/index.mjs`
  - 启动时初始化场景商城目录并挂载 scene 路由。

## 环境与复跑

常用命令：

```text
cd miniapp
npm run dev:h5
npm run build:h5
npm run build:mp-weixin

cd server
npm run check:scene
npm run dev
```

后端启动依赖 `server/.env` 中的 MySQL 与 JWT 配置；真实 `.env` 不提交版本库。
